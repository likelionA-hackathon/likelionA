# PM Connector

**국제 협업의 장벽이던 시차를, 24시간 이어지는 업무 흐름으로.**

한 팀이 퇴근하며 남긴 업무 문서를 AI가 읽고, 다음 팀이 곧바로 이어받을 수 있는 인수인계로 정리합니다.
요약에서 멈추지 않고 **무엇이 중요한지**와 **다음에 무엇을 해야 하는지**까지 연결합니다.

**🔗 [likelion-a-kappa.vercel.app](https://likelion-a-kappa.vercel.app)**
로그인 화면의 **`로그인 없이 테스트해보기`** 버튼으로 가입 없이 전체 기능을 둘러볼 수 있습니다.

## 어떤 문제를 푸나

국경을 넘어 협업할 때 가장 큰 장벽은 언어도 문화도 아닌 **시차**입니다.
Capterra의 2024 Collaboration and Productivity Survey(약 6,500명)에서 국제 협업 구성원이 꼽은 1순위 장벽은
불규칙한 근무시간·시차(44%)로, 언어 장벽(42%)과 문화적 오해(33%)보다 높았습니다.
Harvard Business School 연구(Chauvin et al., 2020)에 따르면 시차가 1시간 늘어날 때
조직 간 커뮤니케이션은 9.2%, 예정된 회의·통화는 10.7% 감소합니다.

지금까지 이 공백은 **사람**이 메웠습니다. 협업 담당자를 두고 실무진-담당자-실무진 구조로 일하는 방식은
정보 전달 단계를 늘리고, 인건비를 만들고, 실무자 사이에는 여전히 소통 공백을 남깁니다.
그리고 담당자를 둘 여력이 없는 1인 기업·프리랜서·초기 스타트업에게는 애초에 선택지가 없었습니다.

PM Connector는 그 자리를 대신합니다. **각자의 업무 환경은 그대로 둔 채, 필요한 정보만 연결합니다.**

## 핵심 기능

### 1. AI 스마트 인수인계
Notion에 남긴 업무 문서를 AI가 읽어 **요약 · 변경사항 · 영향 범위 · 추가 확인이 필요한 항목**으로 재구성합니다.
다음 팀은 문서를 처음부터 읽지 않고 맥락만 넘겨받습니다.

### 2. 긴급도 정규화
조직마다 `Critical`, `P1`, `긴급`처럼 표기가 달라서, 우선순위는 그대로 전달되면 의미를 잃습니다.
공통 기준으로 재정의하고 **원문의 어떤 값을 무엇을 근거로 판단했는지 함께** 남깁니다.
규칙으로 판별되는 표기는 규칙이 처리하고, 그렇지 않은 표현만 AI가 보완합니다.

### 3. 다음 업무 자동 생성
인수인계에서 실행 항목을 뽑아 **담당자 · 마감 · 우선순위 · 상태**가 채워진 초안을 만듭니다.
사람이 한 번이라도 수정하면 `AI 초안` 표시가 사라져, 어디까지가 AI의 제안이고 어디부터 팀의 결정인지 구분됩니다.

### 4. 공유 보드와 보안 필터링
조직 내부 보드와 파트너 공유 보드를 분리하고, 공유 범위는 각 조직이 직접 설정합니다.
상대 팀에 전달되기 전 **어떤 요청이 나가는지 그대로 확인**할 수 있습니다.

### 5. 정보 요청
인수인계만으로 판단이 어려우면 상대 팀에 되묻고, 질문과 답변이 해당 인수인계에 함께 기록됩니다.
다음 담당자가 같은 것을 다시 묻지 않습니다.

### 6. 판단 근거 열람
AI가 정리한 결과는 언제든 **원문과 나란히** 확인할 수 있고, 필요하면 다시 생성할 수 있습니다.
AI의 결론을 그대로 신뢰하도록 요구하지 않습니다.

| 정보 요청 | 받은 질문에 답하고, 보낸 질문의 답을 확인 |

## 동작 방식

```
Notion 문서
    │
    ▼
[동기화]  문서를 가져온다 (페이지 주소만 줘도 내부 DB를 자동 탐색)
    │
    ▼
[AI 정리]  요약 · 변경사항 · 영향 범위 · 추가 확인 항목
    │
    ▼
[긴급도 정규화]  규칙 매칭 → 판별 안 되면 AI 보완 → 판단 근거 기록
    │
    ▼
[다음 업무 생성]  담당자 · 마감 · 우선순위가 채워진 실행 항목 초안
    │
    ▼
[공유 보드]  전달할 항목 선택 → 전송될 요청 확인 → 파트너 팀으로
```

## 기술 스택

| 영역 | 선택 |
|---|---|
| 프레임워크 | Next.js 16 (App Router) · React 19 · TypeScript |
| 스타일 | Tailwind CSS 4 |
| DB · ORM | Neon PostgreSQL · Prisma 6 |
| 인증 | NextAuth v5 · JWT 세션 · Google OAuth + 게스트 로그인 |
| 검증 | Zod — 모든 API 입력 스키마 검증 |
| AI | OpenAI · **프로바이더 추상화 계층으로 Gemini·Claude 교체 가능** |
| 외부 연동 | Notion REST (실연동) · Jira Cloud REST v3 + ADF (요청 규격 생성) |
| 배포 | Vercel (main 푸시 시 자동 배포) |

### 설계에서 신경 쓴 것

- **모델 종속성 제거** — LLM 호출을 `src/lib/llm.ts` 한 곳에 격리해, 환경변수만 바꾸면 다른 모델로 전환됩니다.
- **응답 형태 통일** — 모든 API가 `{ ok, data }` / `{ ok, error }` 한 가지 모양입니다.
  라벨·색·정렬 순서까지 서버가 붙여 내려주므로 화면마다 매핑 테이블을 만들 필요가 없습니다.
- **Notion 입력 관대하게** — 사용자가 표를 복사하면 실제로는 부모 페이지 ID가 넘어옵니다.
  이 경우 하위 블록을 탐색해 인라인 데이터베이스를 자동으로 찾습니다.
- **전 구간 자동 검사** — `npm run smoke` 하나로 엔드포인트 51개 케이스를 검증합니다.

## 빠르게 실행하기

```bash
npm install
cp .env.example .env    # DATABASE_URL / DIRECT_URL 만 채우면 화면은 바로 뜹니다
npx prisma db push
npm run db:seed
npm run dev
```

`http://localhost:3000` 접속. 세팅이 꼬이면 `npm run doctor` 가 원인을 짚어줍니다.

Notion·AI·Google OAuth 연결과 환경변수 전체 설명은 **[`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md)** 에 있습니다.
