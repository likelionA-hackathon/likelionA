# 작업 순서

작성: 백지우 · 2026-08-14

## 원칙

셋이 병렬로 움직이려면 **API 계약과 목데이터가 먼저** 있어야 합니다.
그래서 1순위는 화면이 아니라 "화면이 붙을 수 있는 상태"를 만드는 것이었고, 그건 지금 끝났습니다.

- `docs/API.md` — 엔드포인트 전부 + 응답 JSON 예시
- `src/types/api.ts` — 프론트가 import 할 타입
- `prisma/seed.ts` — 데모 시나리오가 통째로 들어간 목데이터

**아무도 남을 기다리지 않아도 됩니다.** Notion·Claude·Google OAuth 가 하나도 안 붙어 있어도
`npm run db:seed` 만 돌리면 모든 화면이 실데이터를 받습니다.

---

## 0단계 — 전원, 지금 바로 (15분)

1. 레포 clone → `npm install`
2. **Neon DB 하나를 팀이 공유**합니다. 백지우가 `DATABASE_URL` 을 공유방에 올립니다.
   각자 DB 만들면 화면 붙일 때 id 가 안 맞아서 시간 날립니다.
3. `cp .env.example .env` → `DATABASE_URL` 붙여넣기
4. `npx prisma db push && npm run db:seed && npm run dev`
5. `http://localhost:3000/api/me` 가 JSON 을 뱉으면 준비 완료

이 시점에서 각자 `docs/API.md` 의 자기 장(章)만 읽으면 됩니다.

## 1단계 — 병렬 (오늘)

### 백지우 — AI · 연동

| 순서 | 할 일 | 왜 이 순서인지 |
|---|---|---|
| 1 | Notion integration 만들고 데모용 인수인계 DB 3~4건 채우기 | 실연동 시연이 이 서비스의 핵심. 데이터가 없으면 AI 도 못 돌린다 |
| 2 | `POST /notion/sync` 로 실제 요약 생성 확인 | 프롬프트 튜닝은 실제 문서를 봐야 됨 |
| 3 | 요약 품질 안 나오면 `src/lib/claude.ts` 의 SUMMARY_SYSTEM 수정 | 여기만 고치면 됨. 다른 코드 안 건드림 |
| 4 | 우선순위 정규화 케이스 보강 (`src/lib/priority.ts` RULES) | 심사위원이 "Critical 이 왜 긴급?" 물으면 여기 보여주면 됨 |
| 5 | `POST /handovers/:id/actions/generate` 결과 확인 | 데모 4번 장면 |

### 전철우 — 온보딩 · 대시보드 · 연결관리

| 순서 | 할 일 | 붙일 API |
|---|---|---|
| 1 | **대시보드 먼저** (로그인 아님) | `GET /api/workspaces/:id/dashboard` 하나로 끝 |
| 2 | 연결 관리 화면 | `GET/POST .../connections` |
| 3 | 팀 생성 / 초대 링크 | `POST /api/workspaces`, `POST .../link`, `POST /api/links/accept` |
| 4 | 마지막에 Google 로그인 | `AUTH_*` 채우고 `/login` |

> 로그인을 마지막에 두는 이유: OAuth 는 붙이는 데 30분, 막히면 2시간입니다.
> 그 사이 다른 화면이 멈추면 안 됩니다. `DEV_AUTH_BYPASS` 로 그동안 열어뒀습니다.
> 데모에서 제일 오래 보여줄 화면이 대시보드라, 여기에 시간을 제일 많이 쓰는 게 맞습니다.

### 김건희 — 인수인계 상세 · 다음업무 · 공유보드

| 순서 | 할 일 | 붙일 API |
|---|---|---|
| 1 | **인수인계 상세 먼저** | `GET /api/handovers/:id` 하나로 끝 |
| 2 | "확인" 버튼 | `POST .../acknowledge` — 응답이 상세와 같은 모양이라 그대로 갈아끼우면 됨 |
| 3 | 추가확인 항목의 [요청] 버튼 | `POST .../requests` |
| 4 | 다음 업무 (테이블·탭·필터·추가) | `GET/POST .../next-actions`, `PATCH /api/next-actions/:id` |
| 5 | 공유보드 + 미리보기 패널 | `GET/POST .../board` — `targetPayload` 를 그대로 그리면 됨 |

> 상세를 먼저 하는 이유: 데모 흐름의 클라이맥스가 "AI 가 정리한 인수인계"입니다.
> 여기가 허술하면 나머지가 다 잘 돼도 심사에서 안 먹힙니다.

## 2단계 — 합치기 (오늘 밤)

1. 각자 화면을 main 에 머지 (충돌 나는 파일이 거의 없게 폴더를 나눠뒀습니다)
2. **데모 시나리오 1회 완주** — README 의 "데모 시나리오" 6단계를 순서대로
3. 막히는 지점만 고칩니다. 새 기능 추가 금지.

## 3단계 — 데모 준비 (내일 아침)

- `DEV_AUTH_BYPASS="false"` 로 바꾸고 로그인부터 한 번 완주
- 시연 계정 2개(페이팀/정산팀)를 브라우저 2개(일반/시크릿)에 미리 로그인
- Notion 동기화는 **미리 한 번 돌려두고**, 무대에선 이미 있는 데이터로 시작
  (건당 1~3초 걸립니다. 무대에서 로딩 보여주면 흐름이 끊깁니다)
- 네트워크가 죽어도 `npm run db:seed` 로 3초 만에 복구된다는 걸 기억해두세요
